Three steps, about a minute of setup

Sign in once. After that it is paste, adjust, go.

  1. 1

    Sign in with Google

    One consent screen, asking for a single permission: the files this app creates. Your existing Drive stays invisible to it.

  2. 2

    Give it your text

    Paste it, or drop a .txt, .md, .docx or .pdf. Set the speed, how many typos, how often it stops to think.

  3. 3

    Watch it write

    A new Doc appears in your Drive and fills in line by line. Pause it, stop it, or close the tab and pick up where it left off.

Built for how writing actually looks

Every detail exists because the alternative — one enormous paste — looks like exactly what it is.

⌨️

Realistic cadence

Characters arrive in bursts sized from your target speed, with jitter on every one, so nothing lands on a metronome.

🔁

Typos, then corrections

Adjacent-key slips, swapped letters, doubled and dropped characters — typed, noticed a beat later, backspaced, retyped.

💭

Pauses where people pause

At the end of a sentence, between paragraphs, and at random mid-flow. Speed drifts slightly from paragraph to paragraph.

📄

Reads your files

.docx is unzipped in your browser — it never leaves the machine. Text formats are read directly; PDFs go through Drive's own converter.

⏯️

Pause, stop, resume

Interrupt any run without losing it. If the network drops, one click continues in the same document from the exact character it stopped on.

📁

Filed where you want it

Name the Doc and give it a Drive folder. The folder is created if it doesn't exist yet.

Privacy

There is no backend. That is the whole design.

The page you load is static files. Your text goes from your browser straight to Google's own API using a token you grant and that expires in an hour. It is never sent anywhere else, because there is nowhere else — no database, no analytics, no account system, nothing to breach.

The app asks for drive.file, which Google classifies as non-sensitive: it can see and manage only the files it creates. The broader documents permission would have been easier to build against and would have handed it every Doc you own. It isn't requested.

Questions

What do I need before I can use it?

A Google account. Press Sign in with Google, approve one permission, and you're in — the same flow as any other site with a Google button. Sign in once and you stay signed in on that browser.

And if I want to run my own copy?

Then there's a one-time step for you, not for your visitors: create a free Google Cloud OAuth client ID and drop it into src/config.js. It identifies the app to Google so the traffic runs through your project rather than someone else's. The README walks through it.

How long does a document take?

Roughly as long as writing it would. Five thousand characters at 55 wpm is about twenty minutes; the app estimates it before you start. Keep the tab in the foreground, since browsers slow timers in background tabs.

Does the Doc's version history show the typing?

Yes. Each burst is a separate edit, so Google's own revision history shows the document accumulating over time rather than appearing at once.

Can I close the tab while it runs?

No — the typing happens in the page, so it stops when the tab does. Reopening the app and pressing start again continues in the same document from where it stopped.

Is this for cheating on homework?

It types text you already have; it doesn't write anything for you. But it's worth being straight about it: pacing an edit history so work looks like it was drafted over time is something many schools treat as academic misconduct, whoever actually wrote the words. That call is yours, and it's worth knowing the rules you're under before you make it.
